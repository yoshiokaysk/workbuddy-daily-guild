# 第 13 章 时间与任务管理

这一章讲怎么用 WorkBuddy 处理任务拆解、优先级判断和日程安排。这类任务的核心不是"让它替你规划人生"，而是把混乱的输入变成清晰的清单。

## 场景一：任务拆解

一个大目标摆在面前，不知道从哪下手。

### 拆解模板

```text
目标：把下面的大目标拆成可执行的小任务
输入：[目标描述]
背景：
  - 可用时间：[比如每周 5 小时]
  - 截止时间：[日期]
  - 已有资源：[列出]
输出：
  - 按「本周可做 / 下周 / 更远」三档列出
  - 每档不超过 5 条
  - 每条写成一个可立即开工的动作（动词开头）
  - 最后标出"关键路径"上的 3 条（做完才能往下走的）
限制：
  - 每条要具体到"打开什么、做什么"，不要写"研究一下"
  - 不要写"提升重视程度"这类空话
  - 不确定的前置条件单独列出来
```

### 拆得好不好，看两条

1. **能不能立即开工**："调研竞品"不行，"打开 X 网站，记录 5 个竞品的定价"才行。
2. **有没有标出关键路径**：不是所有任务同等重要，先做能解锁后续的。

## 场景二：优先级判断

任务太多，排不出先后。

### 优先级模板

```text
目标：给下面的任务排优先级
输入：[粘贴任务清单]
输出：
  - 按「重要且紧急 / 重要不紧急 / 紧急不重要 / 都不」四象限分组
  - 每个任务给出一句话理由
  - 最后给出"如果今天只能做 3 件，做哪 3 件"及理由
限制：
  - 判断依据只用我提供的信息
  - 缺失的信息（如截止时间）标出来，不要替我假设
  - 不要给"都要做"这种结论
```

### 关键：让它标出缺失信息

优先级判断依赖截止时间、影响范围等信息。如果这些你没给，它会假设。限制里要求"标出缺失信息"，等于让它告诉你还缺什么，而不是替你补。

## 场景三：每日/每周计划

### 每日计划模板

```text
目标：根据下面的任务列表安排今天的工作
输入：
  - 任务清单：[粘贴]
  - 今天可用的时间段：[比如 9:00-12:00, 14:00-17:00]
  - 固定会议：[列出]
  - 我的精力高峰：[比如上午]
输出：
  - 按时间段列出安排
  - 把需要深度思考的任务放在精力高峰
  - 每个任务标注预计用时
  - 留出 30 分钟缓冲
限制：
  - 总任务量不要超过可用时间的 80%
  - 不要安排我提供给你的任务之外的事
  - 时间段冲突要标出来，不要自行调整
```

"不要超过 80%"是防止把计划排满——现实中总有意外，留缓冲才可执行。

### 每周计划模板

```text
目标：把下面的任务安排到本周
输入：
  - 任务清单：[粘贴]
  - 本周固定安排：[会议、截止日]
  - 本周重点：[1–2 件事]
输出：
  - 按周一到周五列出
  - 本周重点任务安排在精力最好的前两天
  - 每天不超过 3 个重点任务
  - 周五下午留复盘时间
限制：
  - 不要把所有任务都排满，标注哪些是"可延后"的
  - 涉及他人的任务标注"需先沟通"
```

## 场景四：复盘与回顾

### 周复盘模板

```text
目标：根据下面的工作记录做周复盘
输入：[粘贴本周完成事项和问题记录]
输出：
  - 本周完成了什么（对照计划）
  - 没完成的及原因（只写记录里有的原因）
  - 一个做得好的做法（说明为什么有效）
  - 一个要改进的点（具体到下次怎么做）
  总字数 400 字
限制：
  - 不要写"下周继续加油"这类空话
  - 改进点要具体到可执行的动作
  - 不要评价我的工作态度，只分析事实
```

## 时间管理场景的边界

这一类任务，AI 给的是**结构化的清单**，不是**替你做决定**。

| 可以做 | 不要做 |
| --- | --- |
| 把大目标拆成小任务 | 决定你的人生方向 |
| 按你给的信息排优先级 | 替你判断什么"重要" |
| 把任务安排到时间段 | 替你向别人承诺时间 |
| 列出缺失信息 | 假设你没说的条件 |

特别是涉及他人的时间安排（"把会议改到周三"），必须由你确认后再发出。

## 高频错误对照

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| "帮我规划一下" | 它不知道你的时间和资源 | 给可用时间、截止时间、资源 |
| 拆解写"研究一下" | 无法开工 | 要求"动词开头、具体到动作" |
| 排优先级时不给截止时间 | 它自己假设 | 要求"标出缺失信息" |
| 计划排满 100% | 一点意外就全乱 | 要求"留 20% 缓冲" |
| 让它决定"什么重要" | 判断权让渡 | 让它分组，你自己定重点 |

## 验收要点

- 拆解：每条能立即开工吗？关键路径标了吗？
- 优先级：判断基于你给的信息吗？缺失信息标出来了吗？
- 计划：有没有超出可用时间？时段冲突标出来了吗？
- 边界：有没有替你向别人承诺、替你做价值判断？

## 小结

- 拆解要"动词开头、可立即开工"，并标出关键路径。
- 优先级判断要让它"标出缺失信息"，而不是替你假设。
- 计划留 20% 缓冲，缺失信息要标出，不要自行调整他人安排。
- 复盘要具体到可执行的改进点，不写空话。
- 它给的是结构化清单，决定权（方向、价值、承诺）在你手里。
