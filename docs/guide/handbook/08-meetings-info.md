# 第 8 章 会议与信息整理

这是日常工作中使用频率最高的场景之一：把原始信息（会议记录、长文档、零散材料）变成结构化结果。本章给出四类任务的操作步骤和模板。

## 场景一：会议记录 → 纪要与待办

### 操作步骤

1. **准备**：拿到完整记录（录音转写文字、手写笔记、聊天记录都行）。
2. **判断用途**：纪要发给谁？他们需要什么？这决定输出结构。
3. **下发任务**：用下面的模板。
4. **验收**：重点检查第 7 章说的"来源"——负责人、时间、结论是否都来自记录。

### 标准模板

```text
目标：把会议记录整理成结构化纪要
背景：这是[部门/项目]的[会议类型]，纪要发给[收件人]，
      他们需要快速知道决定了什么、谁负责什么
输入：[粘贴完整会议记录]
输出：
  1. 一句话结论：这次会议最重要的产出
  2. 已定事项：列表，每条一行
  3. 待办表格：列「事项 / 负责人 / 截止日期」，
     按负责人分组，不超过 10 行
  4. 待确认问题：列表，不超过 3 条
  总字数 600 字以内
限制：
  - 只写记录里明确出现的，不补充、不推测
  - 负责人或时间缺失时写"未提及"
  - 不写评价性内容（如"讨论热烈"）
  - 不加开头引言和结尾总结
```

### 三种常见变体

**变体 A：只要待办，不要纪要**

```text
目标：从会议记录中提取待办
输出：表格，三列「事项 / 负责人 / 截止」，
     每行一条，按截止时间排序
限制：只要待办，其他内容全部不要；
     没有明确负责人的写"待认领"
```

**变体 B：客户会议，需要对外口径**

```text
目标：整理客户会议纪要，用于发给客户确认
背景：[客户名称]，这是需求沟通会
输出：正式邮件格式，结构「会议要点 / 待确认事项 / 下一步」
语气：专业、礼貌、不承诺未确定的事
限制：涉及我方内部判断的内容不要写进去；
     客户提出的需求用"贵方提出"表述，不要写成"要求"
```

**变体 C：快速版，会上实时记**

```text
目标：把我的零散笔记整理成待办
输入：[粘贴速记，比如"老李说周三前给方案 预算要重新算 下周再对一次"]
输出：表格「事项 / 负责人 / 截止」
限制：从速记里提取，看不懂的标"需确认"，不要猜
```

## 场景二：长文档速读

一份几十页的报告，你要在半小时内抓住重点。

### 操作步骤

1. **先要结构**：别一上来就让它总结全文。先让它列目录和每部分主旨。
2. **再选重点**：根据结构，挑你真正关心的部分。
3. **逐段处理**：针对选中的部分提问。
4. **最后合并**：把几段结果整合成你要的格式。

### 模板：第一步，列结构

```text
目标：列出这份文档的结构
输入：[粘贴文档，或前几页内容]
输出：
  - 按章节列出，每章一句话说明主旨
  - 标出每章的字数占比
  - 最后列出你认为最重要的 3 个章节及理由
限制：不要展开讲具体内容，只要结构
```

### 模板：第二步，针对章节提问

```text
目标：基于文档第 X 章，回答我的问题
输入：[粘贴该章内容]
我的问题：[比如"这个方案的成本测算依据是什么"]
输出：答案 + 引用原文中的关键句作为依据
限制：答案必须基于原文，原文没有的写"文档未说明"
```

### 为什么不分两步不行

一次性让它"总结全文"，结果往往是平均用力：每章都写两句，你真正关心的部分反而被压缩。先要结构、再选重点，等于你自己控制了注意力分配。

## 场景三：多份材料汇总去重

比如三份周报合成一份部门周报，或多份反馈整理成一张表。

### 操作步骤

1. **统一格式**：先让每份材料都转成同一个结构（用同一模板分别处理）。
2. **合并**：把转换后的结果放在一起。
3. **去重归类**：让它合并重复项、按类别排序。

### 模板：统一转换

```text
目标：把这份材料转成统一格式
输入：[粘贴第 1 份材料]
输出：表格「事项 / 负责人 / 状态 / 来源」
限制：只提取，不改写；"来源"填材料名
```

对每份材料都跑一遍，得到格式一致的表格。

### 模板：合并去重

```text
目标：把下面的多张表合并成一张
输入：[粘贴几张转换后的表]
输出：
  - 合并重复事项（同一件事只保留一行）
  - 状态冲突的标注出来，不要自行选择
  - 按「事项 / 涉及人 / 状态 / 来源」排列
限制：
  - 不要删掉任何一条不同事项
  - 冲突项用【冲突】标记，保留双方说法
```

::: tip
合并时明确要求"冲突项标注出来，不要自行选择"。否则它会挑一个看起来合理的，把分歧掩盖掉。
:::

## 场景四：零散信息整理

微信群里的一堆消息、便签里的碎片想法，整理成可用的清单。

```text
目标：把零散信息整理成清单
输入：[粘贴聊天记录/便签内容]
输出：
  - 按主题分组，每组一个标题
  - 每组下列出要点，每条一行
  - 把看起来像"待办"的单独归到最后一类
限制：
  - 保留原话的关键表述，不要过度润色
  - 无法判断归属的放"其他"组，不要硬分
```

## 高频错误对照

| 错误做法 | 后果 | 正确做法 |
| --- | --- | --- |
| 只贴材料，不说用途 | 输出形态不对 | 背景里写清"发给谁、要什么" |
| 要求"总结得全面一点" | 平均用力，重点不突出 | 先要结构，再选重点 |
| 合并时让它"自动去重" | 分歧被掩盖 | 要求冲突项标注、保留双方说法 |
| 会议记录贴一半 | 信息缺失，结果不可靠 | 给完整记录；太长就分批处理 |

## 验收要点

这类任务的验收只盯三件事：

1. **有没有编造**：人名、时间、结论都能在原文里找到吗？
2. **有没有遗漏重要项**：你心里知道的关键事项，它在不在结果里？
3. **格式对不对**：能不能直接转发或贴进文档？

## 小结

- 会议记录：先定用途，再用标准模板；三种变体应对只要待办、对外纪要、实时速记。
- 长文档：先列结构、再选重点、逐段处理、最后合并，不要一次总结全文。
- 多份材料：先用同一模板统一格式，再合并去重，冲突项必须标注。
- 验收盯住来源、遗漏、格式三点。
