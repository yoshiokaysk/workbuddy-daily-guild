# 第 9 章 文档与内容写作

写文档是 WorkBuddy 最能省时间的场景之一。关键不是让它"帮你写"，而是把"写什么、给谁看、长什么样"说清楚，让它出可用初稿，你来定稿。本章覆盖日报周报、方案汇报、邮件文案、润色改写四类。

## 场景一：日报与周报

### 为什么日报周报最适合模板化

频率高（每周至少一次）、结构固定、容错率高。一次做好模板，每周改几个词就能用。

### 周报模板

```text
目标：写本周周报
背景：发给[直属领导]，他关注结果和风险，不看过程细节
输入：
  本周完成：[列出完成事项]
  关键数据：[粘贴数据]
  问题与风险：[列出问题]
  下周计划：[列出计划]
输出：结构为
  1. 一句话总结本周
  2. 关键数据（表格式，不超过 5 行）
  3. 完成事项（不超过 5 条，每条一行）
  4. 问题与风险（每条包含"现状/影响"）
  5. 下周计划（不超过 3 条）
  总字数 600 字以内
限制：
  - 只写我提供的内容，缺失数据写"未统计"
  - 不要写"继续努力"这类套话
  - 风险部分要具体，不写"需要关注"这种空话
```

### 写周报的三个技巧

**技巧一：用要点喂，不用散文喂**

给它的输入用简短要点，不要写成长段落。要点越结构化，输出越干净。

**技巧二：要求"每条一行"**

周报最忌讳长段落。明确"每条一行"，收件人才能扫读。

**技巧三：风险写"现状+影响"**

```text
不好：客户那边有点问题。
好：客户接口延迟，影响 B 项目下周三交付。
```

在限制里要求这个格式。

### 日报简化版

```text
目标：写今日日报
输入：[今天的 3–5 条工作记录]
输出：三条——「完成的 / 进行中的 / 明天的计划」，
     每条不超过 20 字，总字数 150 字以内
限制：不要写过程，只写结果和状态
```

## 场景二：方案与汇报材料

### 方案初稿模板

```text
目标：写一份[方案名称]的初稿
背景：
  - 要解决的问题：[描述]
  - 读者：[谁审批，关心什么]
  - 可用资源：[人力/预算/时间]
输入：[你已有的想法、数据、约束条件]
输出：结构为
  1. 背景与目标（200 字内）
  2. 方案概述（一句话说清怎么做）
  3. 关键步骤（3–5 步，每步一句话）
  4. 所需资源
  5. 预期效果与风险
  总字数 1000 字
限制：
  - 用我给的信息，不确定的地方标【待确认】
  - 不要写成"正确但空洞"的通用方案
  - 不要给多个方案让我选，先写一个主线方案
```

### 先把提纲做对，再写正文

方案类文档不要一次性生成全文。分两步：

```text
第一步：只输出提纲
"根据下面的信息，列出这份方案的提纲，
 包含每部分的要点和字数分配，不要写正文。"
```

你确认提纲后，再说：

```text
"按这个提纲写正文，每部分按分配的字数来。"
```

这样避免全文写完才发现结构不对。

### 汇报材料的"结论先行"

给管理层的材料，要求它把结论放最前面：

```text
输出：
  1. 第一段就是结论：现在怎么样、需要你决定什么
  2. 后面才是展开
限制：不要先讲背景再讲结论，直接说结论
```

## 场景三：邮件与沟通文案

### 邮件模板

```text
目标：写一封[主题]邮件
背景：
  - 收件人：[身份，和你的关系]
  - 目的：[希望对方做什么]
  - 语气：[正式/礼貌/简洁]
输入：[需要包含的事实、数据]
输出：
  - 主题行
  - 正文：开头一句说明来意，中间是事实，
    结尾明确"需要对方做什么、什么时候"
  - 总字数 300 字以内
限制：
  - 不要写客套的铺垫（"希望您最近好"之类）
  - 不要替对方做决定
  - 时间、数字用我给的
```

### 几种常用邮件的话术

**延期说明**

```text
目标：写延期说明邮件
输入：[原定时间、新时间、原因、已采取的措施]
输出：说明延期事实 + 原因 + 新时间 + 已采取措施
限制：不找借口，不提内部团队分工，不淡化延期事实
```

**催办**

```text
目标：写一封催办邮件
背景：对方负责的部分已延期 3 天，影响我的进度
输出：陈述事实（哪天承诺、现在什么状态）+ 请求明确时间
语气：就事论事，不带情绪，不指责
限制：不要写"请尽快"这种没有具体要求的措辞，
      要求对方给出明确的完成时间
```

**拒绝**

```text
目标：写一封婉拒邮件
背景：[对方请求、你不能答应的原因]
输出：先明确拒绝（不要含糊），再给简短原因，
     如果可能给替代方案
限制：不要过度道歉，不要给对方"再想想也许能行"的错觉
```

## 场景四：润色与改写

### 常见改写需求

```text
目标：把下面的文字改成[书面语/口语/简洁版]
输入：[粘贴原文]
输出：改写后的全文
限制：
  - 不改变原意和事实
  - 保留所有关键数据
  - 字数控制在原文的 [X]% 以内
```

### 润色的正确顺序

先让它改内容结构，再改文字。一次性要求"既改结构又润色文字"，结果往往两头都不好。

```text
第一轮：只调整结构
"这段文字结构混乱，请重新组织：先结论，后依据，
 最后补充。不要改文字本身。"

第二轮：再润色文字
"基于这一版，把长句改短，删掉冗余的形容词，
 保持原意不变。"
```

### "改成某人的风格"怎么做

不要说"改得高级一点"，给具体参照：

```text
参考这个风格改写：
「本周完成 A、B。C 因接口延迟，顺延至下周三。
  风险：D 依赖外部确认，尚未启动。」
——短句、每句一个信息点、不堆形容词。
按这个风格改写下面的内容：[粘贴]
```

## 高频错误对照

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| "帮我写个周报" | 套话连篇，不能用 | 给要点输入 + 结构 + 限制 |
| 一次性生成全文方案 | 结构不对，全文报废 | 先定提纲，再写正文 |
| "写得专业一点" | 它理解的专业和你不同 | 给一句示例风格 |
| 邮件里让它"替我决定" | 越权，可能不合适 | 只让它整理事实和选项 |
| 改结构+润色一起做 | 两头都不好 | 分两轮 |

## 验收要点

写作类任务的验收，出声读一遍（第 7 章）。重点听：

- 有没有不像你会说的话？
- 有没有编造的事实或数据？
- 收件人能看懂吗？
- 结尾有没有明确的"要对方做什么"？

## 小结

- 日报周报：模板化，用要点喂，要求"每条一行"，风险写"现状+影响"。
- 方案汇报：先定提纲再写正文；给管理层的材料结论先行。
- 邮件：说清收件人、目的、语气；延期/催办/拒绝各有专门话术。
- 润色改写：先改结构再改文字；"改成某风格"要给具体示例，不要用形容词。
