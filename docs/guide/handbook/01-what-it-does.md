# 第 1 章 WorkBuddy 能为你做什么

这一章不列功能清单，而是从"日常工作"的角度，把 WorkBuddy 能接手的活分成四类。你只需要记住这四类，遇到任务时先判断它属于哪一类，就知道该怎么交代。

## 四类可接手的工作

### 第一类：信息处理

把一堆原始材料变成结构化结果。

**典型任务**
- 会议记录 → 纪要、待办清单、决策列表
- 长文档 → 摘要、要点、章节结构
- 多份材料 → 汇总表、对比表、去重后的清单
- 零散信息 → 分类、打标签、排序

**判断标准**：如果你要做的是"读一堆东西，然后整理成另一种样子"，基本属于这一类。

**示例**

```text
目标：从下面的会议记录中提取决策和待办
输入：[粘贴记录]
输出：两部分——「已定事项」用列表，「待办」用表格（负责人 / 事项 / 截止）
限制：只写记录里明确提到的，不补充、不推测
```

### 第二类：内容生成

从零写出一份初稿，或把已有内容改成另一种形态。

**典型任务**
- 写日报、周报、月度小结
- 写方案框架、汇报提纲、邮件
- 把长文改写成短文，把口语改成书面语
- 根据要点扩写成完整段落

**判断标准**：如果你要做的是"从无到有写出来"或"换个说法重写"，属于这一类。

**示例**

```text
目标：写一封延期交付的说明邮件
背景：项目因第三方接口延迟，原定周五交付改为下周三
输入：[项目名、客户称呼、你已经尝试的解决办法]
输出：邮件正文，语气专业克制，不超过 300 字，包含新的交付时间和致歉
限制：不要找借口，不要提内部团队分工
```

### 第三类：任务执行

按你给的规则，对具体内容做批量操作。

**典型任务**
- 把一段文字按固定格式改成表格
- 给一批文件命名、归类
- 按模板批量生成内容
- 按规则检查一份材料是否符合要求

**判断标准**：如果你能说清"输入是什么、输出必须长什么样"，且动作可重复，属于这一类。

**示例**

```text
目标：把下面的客户反馈整理成统一格式
输入：[粘贴 20 条反馈]
输出：表格，列为「客户 / 问题类型 / 原文摘要 / 是否已解决」
规则：问题类型只能从「功能 / 价格 / 服务 / 其他」中选一个
限制：原文摘要不超过 20 字，不要改写客户原意
```

### 第四类：辅助思考

帮你把模糊的想法变清楚，或提供多个视角。

**典型任务**
- 把一个大问题拆成可执行的小步骤
- 列出某个决策的利与弊
- 给你的方案挑毛病、找盲点
- 模拟不同角色的观点

**判断标准**：如果你现在"知道目标但不知道从哪下手"，属于这一类。

**示例**

```text
目标：把"提升团队文档质量"这个目标拆成可执行动作
背景：[团队规模、当前痛点、可用时间]
输出：按「立刻能做 / 一个月内 / 长期」三档列出，每档不超过 5 条
限制：每条要具体到可直接开工，不要写"加强重视"这类空话
```

## 它不擅长什么

同样重要。以下几类不要直接交给它：

| 任务类型 | 为什么不建议 | 正确的做法 |
| --- | --- | --- |
| 需要实时信息的事 | 它不知道今天的最新数据 | 你提供数据，它只做整理 |
| 需要承担后果的判断 | 比如要不要裁撤一个项目 | 让它列利弊，你自己决定 |
| 涉及机密或隐私的内容 | 数据边界要自己把控 | 脱敏后再输入，或不用 |
| 高度依赖个人经验的事 | 它不了解你的具体Context | 你把经验作为背景写进去 |
| 要求"一次到位、不能改"的活 | 初稿几乎总要改 | 预留验收和返工时间 |

## 一个快速判断流程

拿到一个任务，用 30 秒做这个判断：

1. **能不能说清输出长什么样？** 说不清 → 先别交，先想清楚（看第 4 章）。
2. **是不是纯执行、不需要你拍板？** 需要拍板 → 让它出初稿，你做判断。
3. **信息是不是都在你手里？** 不在 → 先补齐信息，或标注不确定部分。
4. **涉及隐私或机密吗？** 是 → 脱敏或放弃（看第 16 章）。

四步都过了，这个任务就适合交给 WorkBuddy。

## 小结

- 日常工作可归为四类：信息处理、内容生成、任务执行、辅助思考。
- 判断依据是"输入—输出是否清晰"，而不是任务听起来高级不高级。
- 需要实时信息、责任判断、机密数据的任务，交给它之前先处理边界。
