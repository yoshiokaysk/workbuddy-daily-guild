# 第 11 章 沟通与协作

日常工作里很大一部分时间在沟通：同步进度、催办、对齐需求、回复客户。这一章讲怎么用 WorkBuddy 把沟通变得省时又不失分寸。

## 沟通类任务的原则

沟通和其他任务不同——**分寸比内容更难**。所以沟通类任务有一条总原则：

> 让它帮你组织事实和选项，语气和分寸由你把关。

永远不要让它"替你说"，而是让它"帮你把要说的话理清楚"。

## 场景一：跨部门同步

### 同步消息模板

```text
目标：写一条跨部门进度同步消息
背景：
  - 发给：[部门/人]
  - 目的：[让对方知道进度 / 请对方配合]
  - 渠道：[邮件 / 群消息 / 私聊]
输入：[进度事实、需要对方配合的事项、时间点]
输出：
  - 开头一句：现在整体到哪一步
  - 中间：和我方相关的事实，列要点
  - 结尾：需要对方做什么、什么时候
  总字数 250 字以内
限制：
  - 不写评价性内容（"大家都很努力"）
  - 不涉及其他部门的内部安排
  - 请求要明确到"做什么+什么时候"
```

### 同步的三个层次

同样一件事，对老板、对平级、对下属说法不同：

```text
对老板：结论 + 风险 + 需要决策的事项
对平级：进度 + 需要配合的事项 + 时间点
对下属：任务 + 标准 + 截止时间
```

下发任务时把"发给谁"写进背景，它会自动调整详略和措辞。

## 场景二：催办

催办最难的是"既要把事推动，又不伤关系"。

### 催办模板

```text
目标：写一条催办消息
背景：
  - 对方：[身份，和你的关系]
  - 事情：[什么事项]
  - 原承诺时间：[日期]
  - 当前状态：[延期了几天，造成什么影响]
输出：
  - 陈述事实：原定 X 日交付，目前状态是 Y
  - 说明影响：这件事卡住了什么
  - 提出请求：请给出明确的完成时间
语气：就事论事，不带情绪，不指责
限制：
  - 不要写"请尽快"这种没有具体要求的措辞
  - 不要推测对方为什么延期
  - 不要提"别人都按期了"这类比较
```

### 催办的升级路径

如果催了一次没用，不要简单重复。分三级：

```text
第一次（提醒）：陈述事实 + 请求明确时间
第二次（升级）：说明影响 + 提出具体时间点 + 抄送相关人
第三次（升级）：说明已经催过两次 + 请求上级介入决策
```

每次下发任务时说明"这是第几次催办"，它会调整语气强度。

## 场景三：需求对齐

和客户或业务方对齐需求时，最容易出问题的是"以为理解了其实没理解"。

### 对齐模板

```text
目标：把下面的一段需求描述转成可确认的清单
输入：[粘贴对方的需求描述，可能是口语化的、零散的]
输出：
  - 按「功能点 / 交付物 / 时间 / 约束」四类整理
  - 每类下用列表列出
  - 最后列出"需要对方确认的问题"，不超过 5 条
限制：
  - 只整理对方明确说的，不替他补全
  - 模糊的地方列为"待确认问题"，不要自行解释
  - 用"贵方"指代对方，不要写成"你们"
```

### 关键：列出"待确认问题"

这个清单是对齐的核心价值。把模糊点全部列出来，发给对方确认，比自己猜着做高效得多。

```text
需要确认的问题示例：
1. "尽快"具体指哪个日期？
2. 报表需要包含历史数据吗？如果包含，追溯到什么时候？
3. 这个需求是否替代上月提出的类似需求？
```

## 场景四：回复客户

### 回复模板

```text
目标：写一封回复客户的消息/邮件
背景：
  - 客户：[身份]
  - 对方来意：[他问了什么/提了什么要求]
  - 我们的立场：[能答应什么，不能答应什么]
输入：[粘贴对方原文、需要包含的事实]
输出：
  - 先回应对方的诉求（表示收到、理解）
  - 再给出我方的答复
  - 最后说明下一步
语气：专业、礼貌、不过度承诺
限制：
  - 不承诺未确定的时间或结果
  - 不替公司表态超出授权的内容
  - 不写"完美""一流"这类形容词
```

## 场景五：把你零散的想法组织成发言

开会前你需要说三点，但想法是乱的。

```text
目标：把我下面的零散想法组织成 3 分钟发言稿
输入：[粘贴你的零散想法]
输出：
  - 开场一句话说明观点
  - 三个论点，每个 1–2 句
  - 结尾一句总结
  总字数 500 字，口语化，适合现场说出来
限制：
  - 用我原话里的关键词，不要换成书面语
  - 不要加我没想到的论点
  - 保留我的观点，不要中和成"各方都有道理"
```

最后一条限制很重要——它很容易把鲜明观点改成四平八稳的套话。

## 沟通类任务的检查清单

发出去之前，逐项确认：

| 检查项 | 通过标准 |
| --- | --- |
| 事实准确 | 时间、数据、状态都来自你给的 |
| 请求明确 | 对方看完知道要做什么、什么时候 |
| 分寸合适 | 语气符合你们的关系和场合 |
| 没有越权 | 没有替公司或他人做承诺 |
| 没有情绪化表达 | 没有指责、抱怨、比较 |
| 没有编造 | 没有把推测写成事实 |

::: tip
沟通类内容一定要出声读一遍。默读时看不出的语气问题，读出来立刻能感觉到。
:::

## 高频错误对照

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| "帮我回复一下客户" | 它不知道你的立场 | 写清"能答应什么、不能答应什么" |
| 催办只写"请尽快" | 对方还是不动 | 要求明确时间点 |
| 让它"帮我解释一下需求" | 它替你补全，造成误解 | 只整理，模糊点列"待确认" |
| 发言稿让它"全面一点" | 变成四平八稳的套话 | 限制"保留我的观点" |
| 不看出声读就发 | 语气问题被发现时已经发出去了 | 发出前出声读 |

## 小结

- 沟通类任务的原则：让它组织事实和选项，分寸由你把关。
- 同步说清"发给谁"决定详略；催办要陈述事实+影响+明确时间，分三级升级。
- 对齐需求时核心产出是"待确认问题清单"，不让 AI 替对方补全。
- 发言稿要明确"保留我的观点"，避免被中和成套话。
- 发出去前出声读一遍，检查事实、请求、分寸、越权、情绪。
